# 手机调色视图

手机壳里的调色入口。引擎、文档和接口与桌面完全同一套：`src/grade/` 负责文档和像素，HTTP 只做打开、改节点、出图，配置写在原片旁边的 `{文件名}.lumeno.json`。本文只定手机端的入口、布局、手势和宿主接口；节点公式以 `docs/color-pipeline.md` 为准，桌面工作区以 `docs/tune-view.md` 为准。

## 范围

手机端做**编辑**，不做资源管理、连线、掩码和工程文件。

- 入口只在照片详情里，视频、只读分享、无写权限的相册不出现。
- 与桌面共用同一份节点文档：手机改过的参数，桌面打开同一张照片时看到的是同一份 `.lumeno.json`。
- 相册网格里的缩略图继续走 `gradedThumb`：保存后下一次进入网格看到的是调色后的缩略图。

第一版覆盖现有节点里的滑杆类：曝光、局部对比、去雾、Velvia、降噪、锐化、Sigmoid，以及 RAW 的白平衡。ColorZones 的曲线和 LUT 选择器要专门的编辑界面，放第二阶段；几何类（旋转、裁切）和输出（导出）放第三阶段：裁切需要另一套手势，导出要选尺寸和格式。

## 入口

照片详情（`frontend/src/mobile/sheets/PhotoViewer.vue`）顶栏加一个「调色」按钮，位置在「查看选项」和「更多」之间；「更多」的操作表里也放同一项，两个入口同一个判断：

| 条件 | 结果 |
| --- | --- |
| 视频 | 不显示 |
| 只读分享 / 无写权限 | 不显示，操作表里置灰并说明原因 |
| 其余照片 | 进入 `grade` 路由，带上当前照片路径和来源相册 |

进入时关闭详情浮层，退出时回到同一个相册位置（滚动、筛选和排序都保留）。用 `useOverlayHistory` 接管返回键：第一次返回关闭调色，而不是退出相册。

## 布局

### 竖屏手机

三级都从底部往上展开：最底下一排是分类图标，点一个分类出现它下面的二级工具按钮，点一个工具才展开这个工具的参数。不弹面板、不做可展开的列表，参数就在工具按钮上方铺开。

```text
+--------------------------------------+
| ✕   文件名 · 调色          ↶  ↷  ✓  |  顶栏，含安全区
+--------------------------------------+
|                                      |
|              预览画布                |  双指缩放，双击 2.5 倍，长按看原图
|                                      |
+--------------------------------------+
| Exposure                    Reset    |  参数区：仅选中工具时出现
| Exposure                     +2.5    |  滑杆整行可拖，双击/长按复位
| ────────────────●──────────          |
| Black                       0.00     |
| ────────●───────────────────          |
+--------------------------------------+
| [☀ Exposure •] [⚙ Sigmoid]          |  二级：当前分类的工具
+--------------------------------------+
|   ☀        ✦        ✧        ⚖      |  一级：分类图标 + 名称
|  影调     色彩     校正     基础     |
+--------------------------------------+
```

- 一级固定四个分类（与桌面同名）：影调、色彩、校正、基础。基础里第一版只有 RAW 的白平衡；没有可用节点的分类不出现。
- 二级是分类里的节点，用节点标题（服务端翻译）和一张小图标；参数与默认值不同的节点带一个小圆点。
- 点同一分类收起到只留一级；点同一工具收起参数区。切换分类时参数区自动收起，避免上一个工具的滑杆留着。
- 滑杆在整行任意位置按下就能拖；温度 / 色调使用带方向的渐变轨道，其余用中性轨道。数字用等宽字体，拖动时实时变化。
- 白平衡的模式用分段按钮（As shot / Temperature / Gains），选到哪一档，下面才出现对应的滑杆。
- 一级、二级按钮高度 44pt 以上；整块面板避开底部安全区。
- 展开是**合成器动画**：面板是一个高度固定的 sheet（52vh），只改 `transform: translateY()`。收起时只露分类行（64px），选中分类后露到工具行（120px），选中工具后完全升起。图片区域不动，图片用 `transform: scale()` 缩放到面板上方的可见区域，所以两种动画都只碰 `transform`，不受 `requestAnimationFrame` 的 60Hz 限制。
- 面板始终是同一套 DOM：参数区、工具行、分类行都在，切换时只换内容和位移，没有逐帧重排。

### 横屏 / 折叠屏

```text
+----------------------------+-------------------+
| ✕  文件名        ↺  ↻  ✓  |  直方图           |
+----------------------------+                   |
|                            |  影调  色彩  ...  |
|         预览               |  ─────●──── +0.35 |
|                            |  ───────●── +1.50 |
|                            |                   |
+----------------------------+-------------------+
| 胶片条（可收起）                                |
+-------------------------------------------------+
```

侧栏 320–380pt，图片占左半边。平板再放宽侧栏并常驻胶片条。

### 胶片条

手机上默认不出胶片条，左右滑动预览切换照片；平板和横屏出底部胶片条，复用浏览网格的缩略图请求（长边 360），当前项高亮。两种方式都走同一个「切换照片」动作，切换时保留上一个会话的参数直到服务端写入完成。

## 手势

| 位置 | 手势 | 行为 |
| --- | --- | --- |
| 画布 | 单指拖动 | 缩放 > 1 时平移；等于 1 时左右切换照片 |
| 画布 | 双指 | 缩放 1–5 倍并平移，松手后小于 1.04 倍回弹到 1 |
| 画布 | 双击 | 1 倍与 2.5 倍之间切换，以双击点为焦点 |
| 画布 | 长按 | 显示原图（第一次打开时的预览），松手恢复 |
| 滑杆行 | 横向拖动 | 调整数值；行内任意位置按下都算，不必抓滑块 |
| 滑杆行 | 双击 / 长按 | 回到该参数的默认值 |
| 滑杆列表 | 纵向拖动 | 滚动；横向拖动交给滑杆，靠方向锁区分 |
| 分组行 | 点按 | 切换分组；再次点按当前分组收起滑杆区 |

所有可点区域不小于 44pt。滑杆的数值用等宽字体显示，调整时轻微触感反馈（`navigator.vibrate` 可用时）。

## 与桌面共用

- **文档与节点**：同一份 `Document`，同一个 `param_from_json`。手机端不重新定义节点参数。
- **会话**：`/api/grade/open` 返回 `rev`、节点、直方图所需的原图预览；`/api/grade/node` 打补丁；`/api/grade/preview` 取当前 `rev` 的预览；`/api/grade/full` 给放大后的清晰图。桌面现有的补丁队列（去抖、`AbortController`、丢弃过期 `rev`）抽成 `composables/useGradeSession.js`，两个壳共用。
- **撤销 / 重做**：客户端保存有上限的节点参数快照（约 30 步），撤销就是把上一份参数再打一次补丁。桌面现在没有这个功能，顺手补上，两端共用同一套历史。
- **对比**：进入会话时的第一帧预览留在内存里，长按显示它，不额外请求。

## 数据流

```text
打开详情 ── 调色 ── POST /api/grade/open { path }
                        │  rev, nodes[], preview(640), writable
                        ▼
                 渲染预览（object URL）
                        │
        拖动滑杆 ── useGradeSession.patch(nodeId, params)
                        │  去抖 80ms，取消上一次请求
                        ▼
                POST /api/grade/node { rev, id, enabled, params }
                        │  新 rev + preview + 服务端写 .lumeno.json
                        ▼
                 替换预览、更新网格缩略图版本
                        │
        松手 ── 再请求一次 preview（丢弃拖动中的中间帧）
                        │
        切换照片 ── open 新路径；旧会话留在服务端，30 分钟过期
```

- 服务端在每次补丁后写 sidecar，所以没有显式的「保存」；失败时保留本地文档，顶部出现「未保存，重试」。
- 只读分享在 `open` 就被拒绝（`writable: false`），手机端在进入前就不显示入口，后端仍然独立校验。
- `rev` 过期（服务端 30 分钟无操作或重启）时，客户端重新 `open` 并把本地参数重放一次。

## 性能

- 预览固定 640 长边（约 80–150 KB JPEG），一次补丁一次请求；拖动时只发去抖后的请求，松手补一帧。
- 图片用 `createImageBitmap` 解码到离屏 canvas，再贴到 `<img>`/WebGL 少一层布局；切换预览时 `revokeObjectURL` 旧图。
- 连续拖动时丢弃返回值而不是排队：`AbortController` + `rev` 序号，和桌面相同。
- 手机端不预取上一张/下一张的 RAW 会话：打开一张 RAW 要 0.5–2 秒，预取会拖慢当前这张。
- 如果弱网下仍然卡，第二阶段给 `/api/grade/preview` 加可选 `edge`（256–2048，默认 640），拖动时请求 480，松手再要 640。

## 分阶段

1. **P1（可用）**：入口与权限判断、全屏编辑器、画布缩放/平移/对比、滑杆类节点（曝光、Sigmoid、Velvia、局部对比、去雾、降噪、锐化、RAW 白平衡）、撤销/重做、横屏布局。
2. **P2（好用）**：ColorZones 的全屏曲线编辑（控制点放大到 16pt 命中）、LUT 选择器、直方图、预设（复制/粘贴参数）、`edge` 参数。
3. **P3（完整）**：裁切与旋转手势、导出（尺寸/格式）、平板与折叠屏打磨、离线队列。

## 未决

- 裁切在手机上是否必须（P1 不做，P3 评估）。
- 手机上是否保留左右滑动切换照片：和画布平移冲突，P1 先只在缩放为 1 时启用，平板改用胶片条。
- 预设是只做「复制上一张参数」还是独立预设库；独立预设库需要新的存储和接口，不应顺带做。
- 手机是否需要「只读查看调色结果」：目前只读分享直接隐藏入口，用户仍能在网格和详情里看到调色后的缩略图。
