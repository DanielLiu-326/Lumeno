# 资源管理器

**资源属于这个登录用户的相册，不属于某一张照片，也不放在** `albums/` **外面。一张 LUT 或一份预设可以被这些相册里的许多照片引用。**

管线语义仍以 `docs/color-pipeline.md` 为准。该文档第 10 节规定种类、内容哈希、别名、校验和内存缓存。本文规定这些资源在 Lumeno 里放哪、管理器给人看什么。调色工作区的范围仍以 `docs/tune-view.md` 为准。本文不改节点公式，也不把调色写进 XMP 或原片。

## 1. 放哪

资源目录在该用户数据根下：

```text
albums/__resource__/lut/
albums/__resource__/preset/
```

`__resource__` 与 `__uploading` 一样，名字以 `__` 开头，不是相册。相册列表、统计和浏览都不把它当成一本相册。种类只来自 `ResourceKind`，目录名是 `lut` 或 `preset`。用户起的名字不能变成目录，也不能变成路径的一段。

每种下面再分载荷、元数据和别名：

```text
albums/__resource__/lut/
  blobs/{hh}/{hash}
  meta/{hash}.json
  aliases/{alias_id}.json
albums/__resource__/preset/
  blobs/{hh}/{hash}
  meta/{hash}.json
  aliases/{alias_id}.json
```

`hh` 是哈希的前一字节，小写十六进制。`hash` 是 64 位小写十六进制。`alias_id` 只允许 `[a-z0-9_-]`，长度 1–64。路径在使用前收口，结果必须留在该用户的 `albums/__resource__/` 下面。带 `../` 的种类、哈希或别名在后端拒绝。

这个目录不进版本库。预览图、去马赛克检查点、缩略图不是资源。它们能从原片和文档重算，不出现在管理器里。

## 2. 种类

管理器列出的种类与 `ResourceKind` 一致：


| 种类       | 目录        | 载荷                       | 照片里怎么引用                  |
| -------- | --------- | ------------------------ | ------------------------ |
| `Lut`    | `lut/`    | `.cube` 原文，不超过 256 MiB，边长 2–256 | LUT 节点参数里的 `ResourceRef` |
| `Preset` | `preset/` | 一份不含照片路径的调色文档            | 照片文档的 `preset` 字段        |


写入后载荷不可改。换一张 LUT 会得到新的内容哈希，旧引用仍指向旧字节。显示名可以改，不参与哈希。

一张 LUT 只存一份。一千张照片引用它，磁盘和解析缓存都是一份。预设内部的 LUT 必须是钉死的 `Pinned`，预设不能再套预设。大小、解析规则和 `ResourceRef` 的序列化沿用第 10 节。

### 2.1 管理器要标出的状态

每一行资源都带这些事实，界面用它们决定要不要提醒：


| 状态   | 含义                       |
| ---- | ------------------------ |
| 就绪   | blob 在，解析能通过             |
| 损坏   | blob 在，但 LUT 边长或预设校验失败   |
| 悬空别名 | 别名还在，指向的哈希已经没有 blob      |
| 被引用  | 至少一份照片文档或预设指向它           |
| 无人引用 | 扫描时没有任何文档指向它，可以回收，但不会自动删 |


回收仍是宿主显式调用 `collect_garbage`。管理器只列出候选人，删除要再确认一次。正在被一次调色执行 `pin` 住的 id 不参与这次删除。

### 2.2 引用关系

管理器要能回答「这张 LUT 被哪些照片用了」。扫描范围是这个用户 `albums/` 下已经保存的调色文档，加上 `preset/` 里预设载荷内部的 LUT 引用。别名先展开成当前目标再计数。不扫描 `__resource__` 以外的缓存目录。

只读分享进来的人可以执行已经写在照片上的引用，从而读到对应 blob。不能向主人的 `__resource__` 导入、改名或删除。写操作只属于这块数据根的主人。

### 2.3 操作


| 操作     | 结果                                                             |
| ------ | -------------------------------------------------------------- |
| 导入 LUT | 先解析 `.cube`，合法才哈希落盘，返回 `ResourceId`                            |
| 导入预设   | 先 `validate_resolved`，其中的 LUT 必须已经在 `lut/` 里                   |
| 改显示名   | 只改 `meta/{hash}.json`，哈希不变，blob 不移动                            |
| 设别名    | 原子更新该种类下的 `aliases/`。系统别名 `system-raw`、`system-raster` 不可被用户覆盖 |
| 删除     | 仍被引用时拒绝。无人引用时删 blob 和 meta。删别名不删 blob                          |


导入失败留在对话框里，不写半份文件。blob 先写到该种类目录里的临时文件，再原子改名到 `blobs/{hh}/{hash}`。同一哈希已存在则跳过 blob，只补元数据。

## 3. 界面

电脑端入口在调色顶栏里，和「返回浏览」同一栏，靠最右边。先进入调色才能看到，不放在浏览网格那条顶栏上。窗口和 AI 工具同一尺寸。左侧栏是菜单，LUT 和预设各一项；右侧是当前这一类的内容。手机不提供这一页。

每一行：显示名、短哈希、被引用次数、状态。点开一行可以看到引用它的照片路径（只显示该用户能看的相册内路径）以及预设内部的引用。悬空和损坏排在前面。

导入在右侧标题「LUT」下面、列表上面。不在顶栏，也不在左侧菜单。预设没有导入。改名和删除在右侧每一行上。删除前若引用次数不为 0，按钮不可用，并写明被谁引用。无人引用时仍要确认。

只读分享不显示导入和删除。


| 情况   | 界面                                                  |
| ---- | --------------------------------------------------- |
| 空    | 说明还没有 LUT 或预设，并给出导入                                 |
| 加载失败 | 保留列表上次的内容，顶上写失败原因                                   |
| 只读   | 可以看、不能改                                             |
| 引用丢失 | 行上标损坏或悬空。执行到缺失的 `ResourceRef` 时该节点报资源错误，预览保持上一帧成功的图 |




## 4. 执行

打开一张照片时，宿主用这本相册主人的 `albums/__resource__/` 解析文档里的 `ResourceRef`。内存里的 `ResourceManager`、`Arc` 解析缓存和 `pin` 仍按第 10 节。`ResourceStore` 的目录实现只读这个相册资源根，不读数据根下的 `resources/`。

LUT 节点仍调用 `open_lut`。`strength = 0` 的 LUT 仍不解析 LUT 文件。

## 5. 权限


| 动作                         | 谁可以             |
| -------------------------- | --------------- |
| 看资源列表、看某张 LUT 被哪些自己能看的照片引用 | 数据根主人           |
| 导入、改名、删除                   | 数据根主人           |
| 调色执行时读取照片已经引用的 LUT 或预设     | 能读这张照片的会话，含只读分享 |


另一账号、过期会话、伪造的种类名、哈希或别名，在后端拒绝。界面上隐藏按钮不算校验。

响应和日志里不写数据根的绝对路径、会话令牌和密钥。显示名当文本渲染。

## 6. 不做

- 不把资源放进某一张照片的目录，也不另建数据根下的 `resources/`。
- 不把 LUT 再复制进每一本相册自己的文件夹。相册之间共用这一份 `albums/__resource__/`。
- 不把资源写进 XMP、原片或 sidecar。
- 不用管理器存放预览、缩略图、去马赛克检查点。
- 不在手机壳里做这个界面。
- 不在这份设计里改增色、影调或其他节点的公式。



## 7. 落地顺序

1. `albums/__resource__/{lut,preset}/` 的目录实现：导入、按哈希读取、别名、显示名。`__resource__` 不出现在相册列表里。
2. 管理器页：列出、导入、改名、显示引用次数。
3. 调色执行从这份目录解析 `ResourceRef`。
4. 回收扫描和「无人引用」列表。删除仍要确认。
